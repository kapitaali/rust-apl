## Remaining Work

### Module 6: Bidirectional Python Communication (Deferred)

**Current state:** Shell-out approach works but is stateless (no persistent Python process).

**Blocker:** Persistent Python process using thread-local `RefCell<Option<PythonProcess>>` + blocking `read_line` causes test deadlocks when `cargo test` runs tests in parallel.

**Possible approaches:**
1. **REPL-managed lifecycle:** `⎕PYTHON.START` / `⎕PYTHON.STOP` as explicit REPL commands (not regular functions) — avoids global state in tests since tests don't call them
2. **`pexpect`-style interaction:** Use a pseudo-terminal for non-blocking I/O
3. **Socket-based IPC:** Unix domain socket instead of stdin/stdout pipes
4. **Accept limitation:** Keep shell-out for now, document that bidirectional requires `pyo3`

**Effort:** 2–3 days (depending on approach).

## Non-obvious notes

- `src/ascii_plot.rs` is fully wired — `⎕APLOT vector` renders a bar chart
- `ValueInner` now uses `CellStorage` enum — pattern matching on `.ravel` won't work; use `cells()`, `cell_at(i)`, or `ravel_mut()`
- `CellStorage::Fetched` uses `OnceLock` for thread-safe lazy caching
- `auto_open` defaults to `false` to avoid `xdg-open` URI handler issues
- All quad functions are in `src/quad.rs`. New ones need: (a) `pub fn quad_X(b: &ValueP) -> AplResult<ValueP>`, (b) wire in `match` in `src/parser.rs` eval, (c) add tests
- GTK is not `Send` — must run on its own thread with channel messaging
- `⎕SEC` enforcement is in `src/security.rs` via `check_sec()`
- GNU APL XML format uses custom type tags: `⁴`=Int, `⁵`=Float, `⁶`=Complex, `¹`=hex codepoint
- `crates/apl-ext/` is the extension crate; `crates/demo-plugin/` is the example
