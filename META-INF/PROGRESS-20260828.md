## Deferred items (future work)

These items are explicitly deferred — not planned for the current session cycle but recorded so they are not forgotten:

1. **Tokenizer spans for caret display** — The tokenizer currently produces a flat `Vec<Tok>` with no source-position information. To display a caret (`^`) under the offending token in error messages (like GNU APL does), each `Tok` would need a `Span { start, end }` into the original input. This is a pervasive change touching the tokenizer, parser, and all error paths — high effort, low functional ROI. Deferred.

2. **Anonymous functions `{}` (dfns)** — APL's dynamic functions `{⍺+⍵}` are a major feature. The parser already has partial `Expr::Dfn` support but no evaluation path. Requires: full brace-body parsing, lexical scoping, `⍺`/`⍵` binding, guarded expressions, and recursion via `∇`. Large feature.

3. **Full ⎕-system** — Currently only `⎕IO`, `⎕CT`, `⎕PP` are implemented. Missing: `⎕CR` (boxed display, partial), `⎕FIO` (file I/O), `⎕NA` (native functions, partial infrastructure), `⎕SQL`, `⎕JSON`, `⎕XML`, `⎕PLOT`, `⎕GTK`, `⎕WA`, `⎕SYL`, `⎕RL`, `⎕RVAL`, `⎕CC`, `⎕DLX`, `⎕FFT`, `⎕FX`, `⎕MAP`, `⎕MX`, `⎕PNG`, `⎕RE`, `⎕SVx`, `⎕TF`, etc. Many of these are optional in GNU APL and require significant infrastructure (GUI, SQL, plotting backends).

4. **Complex numbers** — Parser support exists for `1J2` literals and `Cell::Complex` exists, but most primitive operations on complex numbers are not implemented (tolerant comparison, complex floor/ceiling, complex GCD, etc.). GNU APL uses `APL_Complex` throughout the Cell hierarchy.

5. **Defined-function editor `∇`** — The `∇` editor for defining functions interactively is not implemented. Currently functions can only be defined via `⎕FX` or direct AST construction.

6. **Auxiliary Processors** — GNU APL's AP100 (file server) and AP210 (shared variable server) are not implemented.

7. **Workspace XML persistence** — `)SAVE`/`)LOAD` exists for simple values but the full XML archive format (compatible with GNU APL `.xml` workspaces) is not implemented.

8. **Performance** — No packed arrays, no parallel scalar operations (Rayon is used only in `functions.rs` for elementwise broadcast above 4096 elements), no small-vector optimization.

## Non-obvious notes

- Tokenizer bug fixed: `⍥` handling was missing `#[cfg(feature = "unofficial-ext")]`, breaking default build
- `⍥` (U+2365) and `⌸` (U+2328) are NOT in GNU APL 2.0
- `∘` (U+2218, RING OPERATOR) is matrix product in GNU APL, not compose
- Cell::Char holds u32 codepoint; ValueP::char_vector takes &[u32]
- Prim::Power and Prim::Exponential both map to `bif_exponential` for monadic case
- libapl uses thread-local Environment + Mutex-protected callbacks
- C header `install_get_line_from_user_cb` signature fixed to match Rust fn pointer type
- Dyadic A⌸B: A must be a Char scalar representing a Prim glyph (simplified approach)
