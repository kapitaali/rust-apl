## Session 116 (2026-09-08) — TCP Server Mode + RIDE Protocol

### What was implemented

**`--serve` mode for TCP gateway:**
- `apl --serve <port>` listens on a TCP port and evaluates APL expressions sent by clients
- Each connection gets its own `Environment` (variables persist across evaluations)
- Multi-line results (matrices) handled correctly via end-of-response framing
- Handshake: `SupportedProtocols=2` → `UsingProtocol=2` → `Identify` → `Connect`

**RIDE binary-framed protocol:**
- Framing: `[4 bytes BE total length][4 bytes "RIDE"][JSON payload]`
- Commands: JSON arrays like `["Execute", {"text": "2+2"}]`
- Responses: JSON arrays like `["AppendSessionOutput", {"result": "4"}]`
- Matches the protocol used by the RIDE editor (src/cn.js in the RIDE repo)

**Editor integration:**
- `rust-apl-editor` connects to the server on port 4502
- Ctrl+E sends the current line to the server for evaluation
- Results displayed in the result pane
- Falls back to local evaluation when disconnected

### Verified

```
$ apl --serve 4502 &
$ echo '["Execute",{"text":"2+2"}]' | nc 127.0.0.1 4502
["AppendSessionOutput",{"result":"4"}]

$ echo '["Execute",{"text":"2 3⍴⍳6"}]' | nc 127.0.0.1 4502
["AppendSessionOutput",{"result":"0 1 2\n3 4 5"}]
```
