## Session 22-23 (2026-08-25, evening) — Full dop semantics DONE

### 1. `ApplyOp` and `FuncRef` Expr variants — src/parser.rs

Two new variants added to `Expr`:

- `ApplyOp(Box<Expr>, Box<Expr>)` — defers function resolution to dop-call
  time. Produced when a multi-term dfn body has `⍺⍺`/`⍵⍵` in FUNCTION
  position (`{⍺⍺ ⍵}`).
- `FuncRef(String)` — placeholder for named function references in dop
  bodies; passes through substitute_dop unchanged.

Root cause this session fixed: the old fold code referenced a nonexistent
`Expr::Prim` variant (didn't compile). The real insight: `Tok::Prim(p)`
ALWAYS parses into `Expr::Monadic(p, ...)` via parse_term, so the fold never
sees bare prims.

### 2. Dfn body fold rewrite — parse_dfn_body_expr

Multi-term statements now fold:
- `F X` where F is `⍺⍺`/`⍵⍵` → `ApplyOp(F, X)` (deferred)
- other multi-term cases → `Expr::Seq([e, acc])` fallback (old behavior,
  preserves guards/recursion)
- Prim functions already arrive as Expr::Monadic — untouched

### 3. substitute_dop resolution rules

- `ApplyOp(AlphaAlpha, arg)` + known dop_lo → `Monadic(dop_lo, arg)`
- `ApplyOp(OmegaOmega, arg)` + known dop_ro → `Monadic(dop_ro, arg)`
- unknown operand → stays ApplyOp; eval of unresolved ApplyOp/AlphaAlpha/
  OmegaOmega/FuncRef = SYNTAX ERROR (should be unreachable)

### 4. call_function_dop

New Environment method: clones fn, substitutes operands into body, runs
substituted body through the interpreter loop with branch_stack frame,
shadowing, and current_fn_name save/restore — mirroring call_function.

### 5. Guard body parsing fix (6 test regressions repaired)

parse_dfn_body_expr's guard arm required `s.get(cp+1+bused) == Tok::End`,
but dfn-body statements carry NO trailing End token. Changed to length
check `cp + 1 + bused == s.len()`. This un-broke test_parse_guard,
test_parse_multi_guard, test_dfn_guarded, test_dfn_guarded_multi,
test_dfn_recursive_fib, test_dfn_recursive_nontrivial.

### 6. unparse.rs completion for workspace persistence

Before this session `FAC←{⍵=0:(1) ⋄ ⍵×∇ ⍵-1}` saved as `{!??}` and failed to
load. Added unparse arms for:
- Alpha/Omega/AlphaAlpha/OmegaOmega glyphs
- If (guard desugaring → `c:e ⋄ c:e ⋄ fallback` text; detects terminal
  Num(0) else as no-fallback)
- SelfCall/SelfCallDyad (`∇ x`, `x ∇ y`)
- ApplyOp / FuncRef / AssignDfn
Also removed duplicate match arms that triggered unreachable-pattern
warnings.

### 7. Tests

test_dop_simple: DOP←{⍺⍺ ⍵}; + DOP × 5 → 5 (dop body sees ⍵=5 raw; × is
bound as ⍵⍵ but unused by this body).

REPL verified end-to-end incl. )SAVE/)LOAD round-trip of both a dop dfn and
a recursive guarded dfn (/tmp/test_dop_full.aplws).

## Session 24 (2026-08-25, later) — Dyadic dop calls DONE

### 1. DopCall carries an optional left argument

`DopCall(String, Prim, Prim, Box<Expr>)` →
`DopCall(String, Prim, Prim, Option<Box<Expr>>, Box<Expr>)`.
Monadic form `LO FN RO B` passes None; dyadic form passes Some(lhs).

### 2. Dyadic dop detection in parse_simple — TWO sites

- Monadic site (toks[0..3] = Prim Name Prim): existed; now emits left=None.
- NEW dyadic site after lhs parse: lhs Prim Name Prim rest →
  DopCall(name, lo, ro, Some(lhs), rhs).
- CRITICAL ordering: the dyadic-dop check must precede the plain
  `lhs PRIM rest` dyadic-function arm, otherwise `2 + DOP × 5` parses as
  Dyadic(+, 2, FuncCallMono(DOP,...)) and the dop is invisible.
  (First attempt placed it after InnerProduct but before the plain-dyadic
  arm in one copy only — the working placement is immediately before the
  plain dyadic arm at ~L567.)
- An earlier stray copy of the dyadic check near L454 exists (dead code,
  unreachable because plain-dyadic fires first); harmless, cleanup pending.

### 3. DyadicApply variant for dop bodies

Bodies like `{⍺ ⍺⍺ ⍵}` need INFIX operand application. Fold rule added:
3-term statement whose MIDDLE term is AlphaAlpha/OmegaOmega →
`DyadicApply(A, F, B)`. substitute_dop resolves it to
`Dyadic(dop_lo, A, B)` / `Dyadic(dop_ro, A, B)`.

### 4. call_function_dop binds ⍺ via dfn_alpha_names

AssignDfn strips arg_left from named dfns and parks it in
env.dfn_alpha_names (ambivalent-arity trick from Session 18). First run of
the dyadic dop test failed VALUE ERROR because call_function_dop only bound
f.arg_left — which is None for named dfns. Fix: alpha_name =
f.arg_left.clone().or_else(|| lookup in dfn_alpha_names by name), shadow +
insert when a left value was provided.

### 5. Test

test_dop_dyadic: DOP←{⍺ ⍺⍺ ⍵}; 2 + DOP × 5 → 7 (body {2 + 5}).
NOTE: `2 + DOP 3` is NOT a valid dop call — dop detection requires
Prim Name Prim; a bare number right of the dop name is just a dyadic prim
call. Right operand must be a prim expression.

## Session 25 (2026-08-25, latest) — Extension architecture DESIGNED (not implemented)

User requirement: extendable from C and Java using Dyalog's ⎕NA API
semantics, and ESPECIALLY from Rust, with maximum uniformity across the
three. Source material: Dyalog 19.0 ⎕NA docs (web) + local Dyalog PDFs.

### Deliverable

META-INF/EXTENSIONS.md (commit 9232c33). Key decisions:

1. **One runtime concept**: FunctionTable migrates
   HashMap<String, DefinedFunction> → HashMap<String, Callable> where
   Callable = Interpreted(DefinedFunction) | Native(NativeBinding);
   NativeKind = CAbi | RustPlugin | Java. Single dispatch point.
2. **XArray exchange format**: #[repr(C)] versioned POD mirroring Dyalog's
   `A` type on purpose; ALL ValueP⇄XArray conversion confined to
   src/ffi/exchange.rs (one audit point per direction). Tier-0 scalar path
   vs Tier-1 nested path for cost control.
3. **CAbi adapter = full Dyalog ⎕NA grammar** (<>= direction, 0T/#T strings,
   {} structures, I/U/C/T/F/P/A types, [n]/[] arrays, Dyalog-exact error
   mapping: dlopen fail→FILE ERROR 2, dlsym miss→VALUE ERROR;
   catch_unwind→EXTERNAL EXCEPTION). libloading-based LibraryCache keyed by
   (path, symbol). Workspace persistence = NA text records re-parsed on load
   (never persist pointers). D16 unsupported v1; ∇ callbacks deferred v2.
4. **Rust plugins are the flagship**: separate contract crate crates/apl-ext
   (plugins depend on IT, not the interpreter); typed
   Fn(&CallContext,&[XArray])->Result<XArray,AplError>; two-symbol ABI probe
   (apl_plugin_abi / apl_plugin_create); panic containment; parallel-safety
   opt-in (bind_parallel) — native calls default sequential under Rayon.
5. **Java rides adapter 1's plumbing**: single Rust bridge .so (jni crate)
   exposing ~7 fixed entry points declared VIA ⎕NA itself; Java objects =
   P-typed handles in a global-ref registry; ergonomic JAVA.APLWS wraps raw
   calls in dfns (dogfoods our dfn engine). Feature-gated `java`, off by
   default.
6. **7 phases**, each landing green before the next:
   F1 exchange.rs → F2 nadecl.rs → F3 loader+cabi+⎕NA arm → F4
   FunctionTable migration → F5 apl-ext crate+⎕LOADSO → F6 java → F7
   NA-record persistence+docs.

Module map lives in EXTENSIONS.md §9; open questions (∇ trampolines, =A
aliasing vs copy, non-Linux CI) in §11.
