## Session 22-23 (2026-08-25) — Full dop semantics DONE

### 1. `ApplyOp` and `FuncRef` Expr variants

Added two new `Expr` variants to `src/parser.rs`:

- `ApplyOp(Box<Expr>, Box<Expr>)` — defers function resolution to dop-call time. Produced when a multi-term dfn body starts with `⍺⍺`/`⍵⍵` (or any non-Prim function).
- `FuncRef(String)` — placeholder for named function references in dop bodies (passes through `substitute_dop` unchanged).

### 2. Dfn body fold logic (parser.rs:parse_dfn_body_expr)

Multi-term dfn bodies like `{⍺⍺ ⍵}` now produce `ApplyOp(AlphaAlpha, Omega)`.
- `Prim` functions still fold into `Expr::Monadic(p, acc)`.
- Non-Prim, non-`⍺⍺`/`⍵⍵` functions fall back to `Expr::Seq`.
- The fold correctly handles `{⍺⍺ ⍵}` as `ApplyOp(AlphaAlpha, Omega)` and `{⍵⍵ ⍵}` as `ApplyOp(OmegaOmega, Omega)`.

### 3. `substitute_dop` for runtime binding

`substitute_dop` in `call_function_dop`:
- `ApplyOp(AlphaAlpha, arg)` with `dop_lo` set → `Monadic(dop_lo, arg)`.
- `ApplyOp(OmegaOmega, arg)` with `dop_ro` set → `Monadic(dop_ro, arg)`.
- Other `ApplyOp` variants recurse into both sub-expressions.

### 4. `call_function_dop`

New method on `Environment`:
- Clones the function, runs `substitute_dop` on the body with the operand primitives, then executes the substituted body through the standard interpreter loop.

### 5. Guard body parsing fix

Changed the "body must end with `Tok::End`" check to "body must consume the rest of the statement" — dfn body statements don't have trailing `Tok::End` tokens. Fixed 6 pre-existing test failures (`test_parse_guard`, `test_parse_multi_guard`, `test_dfn_guarded`, `test_dfn_guarded_multi`, `test_dfn_recursive_fib`, `test_dfn_recursive_nontrivial`).

### 6. Unparse fixes for workspace persistence

Added proper unparse rules for:
- `Alpha`, `Omega`, `AlphaAlpha`, `OmegaOmega` (glyphs `⍺`, `⍵`, `⍺⍺`, `⍵⍵`)
- `If` (guard desugaring: `c1:e1 ⋄ c2:e2 ⋄ ...`)
- `SelfCall` / `SelfCallDyad` (`∇ arg` / `larg ∇ rarg`)
- `ApplyOp` / `FuncRef`
- `AssignDfn`

Before: `FAC←{⍵=0:(1) ⋄ ⍵×∇ ⍵-1}` saved as `{!??}` and failed on load.
After: saves as `⍵ = 0:1 ⋄ ⍵ × ∇ ⍵ - 1` and reloads correctly.
