## Session 22-23 (2026-08-25, evening) — Full dop semantics DONE

### 1. `ApplyOp` and `FuncRef` Expr variants — src/parser.rs

Two new variants added to `Expr`:

- `ApplyOp(Box<Expr>, Box<Expr>)` — defers function resolution to dop-call
  time. Produced when a multi-term dfn body has `⍺⍺`/`⍵⍵` in FUNCTION
  position (`{⍺⍺ ⍵}`).
- `FuncRef(String)` — placeholder for named function references in dop
  bodies; passes through substitute_dop unchanged.

Root cause this session fixed: the old fold code referenced a nonexistent
`Expr::Prim` variant (didn't compile). The real insight: `Tok::Prim(p)`
ALWAYS parses into `Expr::Monadic(p, ...)` via parse_term, so the fold never
sees bare prims.

### 2. Dfn body fold rewrite — parse_dfn_body_expr

Multi-term statements now fold:
- `F X` where F is `⍺⍺`/`⍵⍵` → `ApplyOp(F, X)` (deferred)
- other multi-term cases → `Expr::Seq([e, acc])` fallback (old behavior,
  preserves guards/recursion)
- Prim functions already arrive as Expr::Monadic — untouched

### 3. substitute_dop resolution rules

- `ApplyOp(AlphaAlpha, arg)` + known dop_lo → `Monadic(dop_lo, arg)`
- `ApplyOp(OmegaOmega, arg)` + known dop_ro → `Monadic(dop_ro, arg)`
- unknown operand → stays ApplyOp; eval of unresolved ApplyOp/AlphaAlpha/
  OmegaOmega/FuncRef = SYNTAX ERROR (should be unreachable)

### 4. call_function_dop

New Environment method: clones fn, substitutes operands into body, runs
substituted body through the interpreter loop with branch_stack frame,
shadowing, and current_fn_name save/restore — mirroring call_function.

### 5. Guard body parsing fix (6 test regressions repaired)

parse_dfn_body_expr's guard arm required `s.get(cp+1+bused) == Tok::End`,
but dfn-body statements carry NO trailing End token. Changed to length
check `cp + 1 + bused == s.len()`. This un-broke test_parse_guard,
test_parse_multi_guard, test_dfn_guarded, test_dfn_guarded_multi,
test_dfn_recursive_fib, test_dfn_recursive_nontrivial.

### 6. unparse.rs completion for workspace persistence

load. Added unparse arms for:

## Session 26 (2026-08-25, latest) — F1 exchange format DONE

### 1. src/ffi/mod.rs + src/ffi/exchange.rs

New `ffi` module. `exchange.rs` implements the XArray wire format:

- `EXCHANGE_ABI = 1`, `MAX_RANK = 8`
- `#[repr(C)]` `XCell` union (int i64 / float f64 / char u32-codepoint /
  ptr u64) + `XTaggedCell` {tag, cell} with tags Int/Float/Char/Nested
- `XArray`: abi_version, rank, dims[8], elem_count, raw cells pointer,
  len_alloc, children table

**Key design decision (differs from EXTENSIONS.md draft)**: Nested values
are NOT raw pointers across the boundary — a Nested cell's `ptr` field is an
INDEX into the owning array's child table. Children are direct-owned
(Vec<XArray>, freed transitively on Drop). This makes forged/dangling
nested references impossible for foreign code and keeps ownership inside
Rust. Doc updated conceptually here; EXTENSIONS.md §4 amendment pending.

### 2. Ownership discipline (the segfault that taught us)

First version crashed SIGSEGV on test_empty_vector: `Vec::into_boxed_slice()`
on an empty Vec yields an aligned-dangling pointer, and reconstructing
`Vec::from_raw_parts(ptr, 1, 1)` in Drop then freed memory never allocated.
Fix in build(): pad empty ravels to one sentinel element, shrink_to_fit,
assert len==capacity, remember exact len in len_alloc; Drop rebuilds and
frees that exact buffer. Empty arrays now carry one hidden pad cell
(elem_count stays 0).

### 3. Conversions

- value_to_xarray: walks shape+ravel; Pointer cells recurse via
  flatten_level, each nested value becomes a direct child appended to the
  parent's child table in encounter order; Complex/Lval rejected with Err.
- xarray_to_value: check_abi() first (version, rank bound, dims-product ==
  elem_count, nested indices in range, recursive), then rebuild into
  Shape::from_dims + ValueInner::new; Nested cells re-enclose as
  Cell::Pointer(PointerCellData{Arc<ValueInner>}).

## Session 27 (2026-08-25, latest) — F2 ⎕NA declaration parser DONE

### 1. src/ffi/nadecl.rs

Pure parser from Dyalog's ⎕NA grammar to `CAbiSpec { result, library,
symbol, args }`. Design points:

- Word-based: splits on whitespace but keeps `{...}` struct groups intact
  (structs contain spaces). Multi-byte UTF-8 (∇) handled byte-wise in
  split_words.
- Pipe handling: word containing '|' splits at the LAST '|' into
  library|symbol; exactly ≤1 word before it may be the result. No-pipe form
  also accepts dotted lib.symbol (`mydll.foo`).
- Result disambiguation (no pipe): if ≥2 words and word[0] is entirely
  typespec-alphabet chars, word[0] is the result.
- TypeSpec carries dir (<>=), special (0/#), leaf type, width, array_len /
  array_open, struct members.
- UTF8/UTF16 parsed as units; ∇ recognized via first UTF-8 byte 0xE2
  (PITFALL: matching 0x2207 against a u8 silently truncates to 7 — caught
  by deny(overflowing_literals)).
- Validation pass: per-type legal widths (I/U:1-2-4-8, C/T:1-2-4, F:4-8,
  J:16), special-without-direction → DOMAIN, Out-result → DOMAIN, >12 args
  → SYNTAX, D16 and ∇ deferred → DOMAIN with clear semantics.

### 2. src/ffi/nadecl_tests.rs — 27 tests

Every example family from the Dyalog doc:
- canonical `'F8 math|divide I4 I4'` incl. irregular whitespace variant

- fixed/open arrays `I[10] U U[]`; scalar-vs-vector FooScalar/FooVector

- real-world lines: advapi32 registry family, kernel32, user32, gdi32,

## Session 29 (2026-08-25, latest) — F3b pointer/string args DONE

### 1. cabi.rs: buffer management for < > = arguments

- Direction::Value args unchanged (scalar words).
- Pointer args (< > =): build_arg_buffer allocates a C-side byte buffer;
  its ADDRESS is the shim word. Buffers kept alive in `owned` until after
  the call.
  - `<X`/`=X` filled from the APL value; `>X` zero-filled, sized by [n]
    or the value's element count (min 1).
  - Enclosed args unwrapped one level first (scalar Pointer cell → inner
    array) so `(⊂1 2 3 4)` marshals as the vector itself.
- Strings via special codes: 0T = NUL-terminated (input appends NUL;
  output over-allocates input+64), #T = byte-counted. T4/wide encodes
  UTF-8 for C-string semantics.
- read_out_buffer converts buffers back: strings truncate at NUL; numeric
  arrays decode per width into rank-1 vectors.

### 2. Result assembly (Dyalog rule)

Declared scalar result (if any) + each >/= output ENCLOSED, appended in
declaration order — a single-item or empty case collapses to plain value /
shy-nil.

### 3. sig computation narrowed

Only by-value F8 scalars use xmm; pointer args are gp-register addresses.

## Session 32 (2026-08-25, latest) — F3c struct arguments DONE

### 1. C-layout struct support in cabi.rs

`{I4 F8}`-style struct args now work through the >{} pointer path:
- `struct_layout()`: computes per-member (offset, size) following C rules —
  each member aligned up to its natural alignment, total rounded to max
  member alignment (= C sizeof). {I4 F8} = I4@0 + 3 pad + F8@8, size 16.
  (First attempt padded the PREVIOUS member's span instead of aligning the
  NEXT member's start — wrong for mixed-width members; caught by REPL test
  showing weight=0.)
- `fill_struct_buffer`: APL arg is enclosed vector; item i fills member i
  into its layout span (LENGTH ERROR on count mismatch)
- `read_struct_buffer`: members re-read from spans, each ENCLOSED into a
  nested result vector (Dyalog shape)
- build_arg_buffer / read_out_buffer dispatch structs; check_arg still
  rejects by-value structs ({...} must travel via >{} pointers)

### 2. Out-only args consume no APL inputs

Dyalog semantics: `>` args are RESULTS, not call arguments.
`mk 7 2.5` supplies 2 items to a 3-declared-arg function (I4 F8 >{I4 F8}).
- explode logic counts only non-Out args (`input_args`)
- arg-prep walks spec with an iterator over exploded items; Out args
  allocate buffers without consuming input
- result assembly iterates the spec so owned buffers mirror arg order

Verified: `p2 ← mk 7 2.5`; `⊃p2` → `(⊂7)(⊂2.5)`; `0⊃⊃p2` → `7 2.5`;
`r2[0]`=7 (tag), `r2[1]`=2.5 (weight).

### 3. Discovered pre-existing bug (NOT an F3c regression)

`x←⊂8` ⋄ `y←x[0]` ⋄ `5+y` → DOMAIN ERROR. index_value returns the raw

## Session 35 (2026-08-25, latest) — F6 Java bridge scaffold DONE

### Design (per EXTENSIONS.md §7): Java rides adapter 1

No third adapter mechanism. libapljava.so is itself a CAbi-consumable
.so; the interpreter associates its symbols with ordinary ⎕NA strings.
New crate crates/apl-java (cdylib, workspace member).

### Bridge surface implemented (skeleton)

- j_init <0T → P        : create JVM state (v1 single-JVM; -1 if already up)
- j_ready → I4          : 1 once j_init succeeded
- j_live_handles → P    : diagnostics count
- j_free P P → I4       : drop a handle from the registry

Handle currency: u64 from a process-global AtomicU64 counter, stored in

Invocation API calls into the same signatures.

### 2. PANIC CONTAINMENT ACROSS THE BOUNDARY — the hard lesson

First design put catch_unwind in the host's PluginBinding::call. FAILED:
host and plugin are separate Rust compilations; a panic unwinding through
libloading into a different std runtime aborts with "Rust cannot catch
foreign exceptions". Fix: Registrar::bind ITSELF wraps every user function
in catch_unwind at registration time — this generic code instantiates in
the PLUGIN's crate, so panics unwind inside the plugin and are converted
to Err(AplError::msg("EXTERNAL EXCEPTION in <name>")) before crossing.
Host-side catch_unwind kept as belt-and-braces.

Also required: workspace root [profile.release] panic = "unwind" (lto=true
alone doesn't force abort, but an explicit guarantee is documented there;
demo-plugin must NOT override profiles — non-root profiles warn+ignore).

### 3. src/ffi/plugin.rs — host loader

load_plugin(): dlopen (LibraryCache search incl. APL_LIB_PATH) → ABI
probe (mismatch = descriptive error) → create → rebuild → register →
PluginBinding per entry. PluginBinding::call: arity check, Mutex-guarded
fn access, host-side catch_unwind backstop, error text → stderr +
DOMAIN ERROR. value_to_xvalue / xvalue_to_value conversions (nested cells
rejected at boundary).

### 4. Interpreter wiring

- Callable::Plugin variant + FunctionTable::insert_plugin
- Expr::QuadLoadSo parse arm (`⎕LOADSO 'path'`) + eval arm: loads,
  registers all bindings, returns space-joined names as char vector
- call_plugin(): passes the right arg as ONE XValue (plugins declare
  their own arity — NO ⎕NA-style item explode); scalar enclosures unwrap
  one level first
