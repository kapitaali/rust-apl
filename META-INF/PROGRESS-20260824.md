## Session 19 (2026-08-24) — dfn persistence + is_dfn field DONE

### 1. dfn `no_save` bug fixed — named dfns now persist through )SAVE/)LOAD

The root cause: `dfn_to_function()` set `no_save: true` on ALL dfns (including
named ones created via `NAME←{BODY}`), and `save()` blindly skipped anything
with `no_save`. Named dfns therefore worked in-session but vanished on )SAVE.

Two changes:

a) `save()` now skips only anonymous dfn temporaries (identified by the
   private-use `\u{f0000}dfn` name prefix), not the `no_save` flag. Named
   dfns reach the `is_dfn` branch.

b) New `DFN` workspace record type: `DFN <name> <unparsed-body>`. The
   named-dfn branch calls `unparse::unparse(&f.body[0])` to get canonical
   APL and writes a single self-contained line. `load()` recognizes
   `DFN` records, reconstructs `NAME←{body}`, and evals it — the existing
   `AssignDfn` path does the rest.

c) `is_dfn` field added to `DefinedFunction` (was missing from two
   constructors — latent compile error now fixed).
