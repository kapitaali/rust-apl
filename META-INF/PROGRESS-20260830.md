### Module 2: Fetcher Function Pointer (Phase 7.4)

**Current state:** Deferred. `ValueInner` stores ravel as `Vec<Cell>`. No way to compute cells on-the-fly.

**What it does:** Stores a function pointer `(fn(index: usize) -> Cell)` instead of a materialized ravel. Enables lazy arrays, repeated-value arrays without storage, and avoids per-cell branching for packed/unpacked.

**Steps:**
1. Add variant to `ValueInner`:
   ```rust
   enum ValueInner {
       // ... existing ...
       Fetched { shape: Vec<usize>, fetcher: Box<dyn Fn(usize) -> Cell + Send + Sync> },
   }
   ```
2. Add constructor `ValueP::from_fetcher(shape, fetcher)`.
3. Update `cells()` / `ravel()` to call the fetcher when needed.
4. Add `Index` impl that uses the fetcher for random access.
5. Update all match arms that access `ValueInner::Ravel` — add `Fetched` arm.
6. Write tests: `test_fetcher_constant`, `test_fetcher_sequence`, `test_fetcher_materialize`.

**Effort:** 1 day. Internal perf, no external deps.

### Module 5: GTK GUI (⎕GTK)

**Current state:** Stub returns `DomainError`.

**What it does:** Opens a GTK4 window for interactive APL display — text, tables, plots.

**Steps:**
1. Add `gtk4 = { version = "0.7", optional = true }` to Cargo.toml.
2. Implement `quad_gtk`:
   - Initialize GTK on first call (guard with `Once`).
   - Spawn window in a dedicated thread (GTK is not `Send`).
   - Channel-based messaging: APL sends `GtkMessage::ShowText(s)` / `GtkMessage::ShowPlot(path)` → window thread renders.
3. Define message protocol:
   ```rust
   enum GtkMessage { ShowText(String), ShowPlot(String), ShowTable(ValueP), Close }
   ```
4. Add `⎕GTK` grammar:
   - `⎕GTK 'text' 'hello world'` → open/update window with text
   - `⎕GTK 'plot' 'plot.png'` → show image
   - `⎕GTK 'close'` → close window
5. Handle window lifecycle: first call opens, subsequent calls update.

**Effort:** 1–2 days. Needs `libgtk-4-dev` on the build machine.

### Module 6: Bidirectional Python Communication

**Current state:** Not started. Depends on Module 4.

**What it does:** Persistent Python process. APL can send values, get results, and maintain Python state across calls.

**Steps:**
1. Create a `PythonProcess` struct:
   ```rust
   struct PythonProcess {
       stdin: ChildStdin,
       stdout: ChildStdout,
       child: Child,
   }
   ```
2. Start on first `⎕PYTHON` call (or explicit `⎕PYTHON.START`).
3. Communication protocol: newline-delimited JSON.
   - APL → Python: `{"cmd": "eval", "code": "..."}`
   - Python → APL: `{"ok": true, "result": [...]}`
4. Maintain a global `Mutex<Option<PythonProcess>>` (lazy_static or once_cell).
5. Add commands:
   - `⎕PYTHON 'code'` — eval, return result
   - `⎕PYTHON.SET 'var' value` — set Python variable from APL
   - `⎕PYTHON.GET 'var'` — get Python variable to APL
6. Handle errors: Python exceptions → APL `DOMAIN ERROR`.
7. Add shutdown: `⎕PYTHON.STOP` or at `)OFF`.

**Effort:** 2–3 days. Depends on Module 4.

## Non-obvious notes

- All quad functions are in `src/quad.rs`. New ones need: (a) `pub fn quad_X(b: &ValueP) -> AplResult<ValueP>`, (b) wire in `match` in `src/parser.rs` eval, (c) add tests.
- `ValueInner` is the core value representation. Adding a variant requires updating ALL match arms.
- `src/ascii_plot.rs` already exists with `quad_aplot` — just needs dispatch wiring.
- GTK is not `Send` — must run on its own thread with channel messaging.
- `pyo3` requires Python dev headers and a compatible Python version.
- `⎕SEC` enforcement is in `src/security.rs` via `check_sec()`.
- GNU APL XML format uses custom type tags: `⁴`=Int, `⁵`=Float, `⁶`=Complex, `¹`=hex codepoint.
- `config.toml` controls plugin inclusion at compile time.
- `crates/apl-ext/` is the extension crate; `crates/demo-plugin/` is the example.
